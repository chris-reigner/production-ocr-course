Production OCR on AWS EKS

The deployment, end to end

Six steps, in order — each one has to land before the next has anything to stand on.
STEP 1
Terraform foundation
The base AWS layer, entirely as code: a VPC with public and private subnets, an EFS volume for shared model weights, the IAM roles, and the OIDC provider that later lets pods borrow AWS permissions.
VPC & subnetsEFS (RWX)IAM rolesOIDC provider
STEP 2
Cluster configuration
Carve the EKS cluster into node groups — CPU, high-memory Redis, and two GPU pools (T4 and L40S). Taint the GPU nodes so only GPU work lands there, and install the NVIDIA device plugin.
Node groupsGPU taintsDevice plugin
STEP 3
EKS deployment
Build the three images to ECR, then layer the stack in order: KEDA for scaling, the ingestion Job that fills EFS with weights, the vLLM server, and the Rust producer with the layout worker.
Images → ECRKEDAIngestion JobvLLM serving
STEP 4
Terraform infra & authorization services
The secure edge, provisioned as code: an internal NLB, API Gateway reaching in over PrivateLink, WAF, and a Cognito/OIDC JWT authorizer so every request is authenticated and throttled before it reaches a pod.
API GatewayPrivateLinkWAFCognito / OIDC
STEP 5
Monitoring setup
Wire up the metrics that matter — none scrape by default. A DCGM exporter gives GPU telemetry, and a ServiceMonitor on vLLM's queue depth feeds both Grafana and the KEDA autoscaler.
PrometheusGrafanaDCGM exporterServiceMonitor
STEP 6
Testing & validation
Follow one request end to end: tail each tier's logs, mint a Cognito token, push a real PDF through the public gateway, and confirm both the OCR round-trip and the metrics landing in Prometheus.
Cognito tokenPDF OCREnd-to-end round-trip
